# 架构与接口

## 目录与模块

| 目录或入口 | 职责 |
| --- | --- |
| `plugin.py` | MaiBot 生命周期、组件注册、基础工具、Hook、状态指令与首页入口 |
| `config.py` | SDK 配置模型及中文字段说明 |
| `core/` | `engine.py` 推进状态与管理记录，`models.py` 定义业务输入，`store.py` 保存生活数据 |
| `life/` | `living.py` 规划活动，`spatial.py` 管理地点与移动，`rhythm.py` 展开重复日程与学习习惯 |
| `life/` | `books.py` 管理阅读，`diary.py` 生成日记，`dreams.py` 生成梦境，`continuity.py` 接续活动与目标，`anniversaries.py` 管理人物生活资料与纪念日 |
| `integrations/` | `usage.py` 调用模型并记录用量，`memory.py` 连接原生记忆，`world.py` 获取天气与联网资料，`share_receipts.py` 核对主动交流回执 |
| `interfaces/` | `feature_tools.py` 提供对话工具，`webui.py` 提供页面 API，`review.py` 处理记忆冲突确认 |
| `webui/`、`webui.json` | 页面内容、样式及原生工作区声明 |
| `assets/` | 图标等资源 |
| `tests/` | 功能与耦合测试 |

MaiBot 通过根目录的 `plugin.py` 加载插件。入口组装各模块，页面与对话工具调用生活功能，数据由 `core` 保存和推进。生活模块通过 `integrations` 使用 MaiBot 与外部服务。

生活数据使用 SQLite 保存，记录按类别和 ID 组织，写操作通过事务提交。

## 状态转换

```text
scheduled → active → completed（独自模拟）
                   → awaiting_confirmation（共同安排或非模拟）
active → paused → active
scheduled → blocked（后续固定安排无法按时到达）→ scheduled（调整后恢复）
scheduled / active / paused / awaiting_confirmation → cancelled
记录带 plan_id 的已发生经历 → completed
```

取消安排后仍可补录经历。补充内容写入原经历，修改标题和时间时沿用原计划 ID，历史修改记录一并保存。

状态推进按计划的开始和结束时间分段处理，跨午夜和离线恢复使用同一套结算规则。空闲时间按经过的时长更新身体状态。活动选择比较日程、目标、环境和身体需求的变化，发生变化时重新规划；同一情境按规划间隔检查。

角色独自完成活动后生成具体结果，用户补充的细节优先保留。活动归类用于习惯学习与作品接续，偏好关联对应经历。分阶段目标按活动结果推进，旧目标沿用完成次数累计方式。跨日接续沿用 continuation_id 对应的作品记录，结果保存完成状态；经历中的进度修订同步到接续内容。

路线按当前地点、正在进行的活动和后续活动依次计算。出行安排随活动生成；固定活动发生冲突时标记为 blocked，可变动活动顺延。情绪影响随时间减弱，跟进事项保存话题内容与请求状态。

## MaiBot 接口

- 使用 SDK 2.21 的插件工厂、配置模型、工具、首页卡片和命名 Hook。
- 接收 Hook 匹配完整的状态指令，调用 `chat.open_session` 打开原生会话后发送查询结果。状态回复使用 `storage_message=False` 和 `sync_to_maisaka_history=False`，随后结束本次指令处理。
- Planner Hook 注入 `SystemMessageItem`；Replyer Hook 追加 `extra_prompt`，自然语言操作仍经过原生对话流程。
- 会话与用户取自 MaiBot 提供的 `stream_id`、`user_id`。
- 自然交流使用 `ctx.maisaka.proactive.trigger()`；主动表达使用 `ctx.maisaka.reply.generate()` 生成文本，通过 `ctx.send.text()` 发送并同步原生聊天历史。两种模式按实际发送回执结算额度。
- 原生记忆通过 WebUI 的 A_Memorix HTTP 接口查询、创建与更新。
