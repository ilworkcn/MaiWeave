# 功能与数据说明

[文档目录](README.md) · [使用手册](使用手册.md) · [配置指南](配置指南.md)

这页说明一项安排怎样变成生活经历，以及这些记录如何用于聊天、日记和记忆。具体操作见使用手册。

## 一项安排如何进行

你可以在聊天里约麦麦读书、出门或一起看电影，也可以在「日程与作息」新建安排。开启自主活动后，麦麦还会结合时间、兴趣、精力和已有约定，安排自己的空闲时间。

| 日程状态 | 含义 | 可以做什么 |
| --- | --- | --- |
| 待进行 | 已排好时间，等待开始 | 修改时间、地点或取消 |
| 进行中 | 活动正在进行 | 查看进度、暂停或取消 |
| 已暂停 | 活动暂停，记录保留 | 继续活动或取消 |
| 需要调整 | 固定活动与其他安排或出行时间冲突 | 修改时间、地点或路线 |
| 等待确认 | 共同安排等活动已到结束时间，等待实际完成情况 | 在聊天里说明做了什么，补充经历 |
| 已完成 | 已记录完成结果 | 回看感想、补充或更正细节 |
| 已取消 | 安排已取消，历史记录保留 | 查看取消经过；实际发生过的部分仍可补录经历 |

独自模拟活动结束后会整理结果；一起约好的事由聊天中确认的情况形成经历。活动的地点、天气、阅读内容和感想，会参与之后的聊天与日记。

重新加载插件后，会按已有日程和经过的时间更新进度与身体状态。活动改变时重新考虑接下来的安排，情况相同时按配置间隔检查。

## 计划与经历分别记录

| 内容 | 记录的是什么 | 例子 |
| --- | --- | --- |
| 计划 | 准备做的事 | 明晚八点一起看电影 |
| 用户陈述 | 你讲述的已发生事情 | 昨晚看完了电影，中途停电了一会儿 |
| 交互观测 | 当前交流中已经确认的互动，附依据 | 一次已确认的约定或交流结果 |
| 模拟经历 | 角色在生活引擎中独自完成的活动 | 午后散步、做饭的过程与结果 |

补充或更正经历时，原来的来源类别和修订历史会保留。已关联的日程、作品进度也会使用修订后的内容。

书架阅读记录使用「交互观测」来源，保存已读取的正文范围，并分别展示内容摘要、原文摘句和角色读后感。

天气和城市资料来自接入服务，阅读内容来自上传的书籍；角色的出行、作息和身体状态由生活引擎模拟。经历页面可以查看具体内容与来源。

## 聊天怎样用上生活记录

普通聊天会根据当前话题带入生活状态、人物近况、相关日程、阅读笔记和近期经历。群聊与私聊的信息量分别配置，完整记录也可以通过对话工具查询。

聊天提出的新安排会写入日程，日程里的结果又会用于后续交流。双方说定的角色调休、请假和临时改期，会保存原话依据、所属聊天流和有效时间。自主活动参考这些约定；日程修改沿用已有的时间冲突与出行处理，当天的临时变化保留其他日期的重复规则。读了一半的书和没完成的作品会保留进度，长期目标可以按阶段推进。

`/maiweave` 等状态指令直接展示查询结果。指令和状态回复按管理消息处理，聊天观察、历史上下文和 Planner 跳过这次查询。自然语言问“今天做了什么”则照常进入聊天。

人物近况按 MaiBot 人物身份关联，因此同一个人在群聊和私聊中的“去忙了”“准备睡了”等状态可以接续。各会话中的安排和资料按所属聊天流使用，公共自主活动与角色身体状态由各聊天流共享。

## 主动交流与普通回复

普通回复跟随 MaiBot 当前聊天流程，并参考麦麦的睡眠静默规则。主动交流会另外检查生活状态、接收对象、时间、间隔、额度和可分享内容。

私聊刚有来有回时，普通分享先留着。稍后再看最近的话题和对方的期待，决定这件小事还值不值得单独发。麦麦答应到站或办完事后回来报信时，约定会关联到具体日程。改期就跟着等，取消或已经答过就结束。

- **自然交流**：将候选话题交给 MaiBot Planner，结合当前聊天决定是否开口。
- **主动表达**：选好内容后调用 MaiBot Replyer 生成并发送。

普通分享和提醒按实际送达计数，同一次分段发送计一次。关联日程的回信单独计，仍遵循发送时段和睡眠状态。主动交流卡片可以查看模式、接收对象、今日次数、等待事项和最近原因。开启作息问候后，早晚安随睡眠安排寻找时机。

## 原生记忆与生活档案

人物画像和通用记忆使用 MaiBot 的 A_Memorix。MaiWeave 通过记忆连接读取人物资料，并按用户操作同步经历或修改画像。

用户讲述与已确认互动形成的经历可以同步到原生记忆，后续修订也会更新对应内容。角色模拟经历、梦境、书籍与阅读进度保存在 MaiWeave 的生活档案中。

写入人物资料、纪念日或记忆时，会比较已有内容。相容的补充直接保存；出现矛盾时，页面列出差异供你修改或确认。

## 数据保存在哪里

生活记录存放在 MaiBot 为插件分配的数据目录，通常为 `data/plugins/ilworkcn.maiweave/`。其中包含生活数据库、上传的书籍原文件和解析正文。备份时保留整个目录和插件配置，操作见[数据与备份](使用手册.md#数据与备份)。

模型调用明细、运行记录和普通经历按「高级设置 → 数据保留」整理。日记、空间发布记录、阅读笔记和梦境长期保存。MaiBot 原生记忆由 MaiBot 管理。

## 外部服务与接入

| 功能 | 使用的服务 | 去哪里设置 |
| --- | --- | --- |
| 生活规划、阅读、日记等 | MaiBot 模型任务 | 插件配置 → 模型设置 |
| 天气与城市定位 | Open-Meteo、心知天气 | 插件配置 → 天气与见闻 |
| 搜索、网页读取、城市地点资料 | MaiBot 已配置的联网服务 | MaiBot 模型管理与插件天气设置 |
| 人物画像与通用记忆 | MaiBot A_Memorix | 插件配置 → 交流与记忆 |
| QQ 空间发布 | OneBot 适配器连接的 SnowLuma / NapCat | 连接器及插件生活日记设置 |
| 给其他插件提供状态 | MaiBot 跨插件 API | 调用方声明 `api.call` 能力 |

其他插件可以调用 `get_life_status` 查看生活状态，调用 `evaluate_behavior` 查看交流判断，或用 `get_relationship` 查询指定对象的关系，查询过程保持生活记录原样。参数、字段、时间含义和示例见[只读状态 API](只读状态API.md)。

### 生活图片与写作素材

`integrations/diary_images.py` 直接调用配置的 OpenAI 兼容图片生成接口；空间随笔与聊天图片共用请求、文件保存和用量记录。私人日记保存文字。两类记录分别保存 `image_prompt`、`image_file`、`image_status` 与 `image_error`，正文状态独立记录。图片请求在线程中执行。

日记读取当天聊天，每个聊天流最多选取 2500 字符，总消息素材预算为 10000 字符。聊天片刻保留素材编号和聊天流归属；最终写作的各类素材合计预算为 18500 字符。空间文案使用聊天片刻的公开摘要，配图使用对应正文的场景描述与配图风格，人物画面还会加入共用的麦麦角色卡。

配图由 `core/image_retention.py` 按保留天数、总张数和文件容量整理，接入生成完成与原有每日清理入口。清理同步移除记录中的文件引用，保留正文、画面描述和发布状态；正在生成、发布或等待核对的图片在处理结束后参与清理。


### QQ 空间发布接口

通过 `ctx.call_capability("api.call", ...)` 调用 OneBot 适配器公开 API，接口版本均为 `1`：

| 用途 | API | 参数 |
| --- | --- | --- |
| 客户端信息 | `adapter.napcat.system.get_version_info` | 空对象 |
| 登录账号 | `adapter.napcat.system.get_login_info` | 空对象 |
| SnowLuma 发布 | `adapter.snowluma.qzone.send_qzone_msg` | `params` |
| NapCat 空间登录信息 | `adapter.napcat.account.get_cookies` | `params={"domain":"qzone.qq.com"}` |

SnowLuma 发布的 `params` 包含正文 `content`、可见范围 `ugc_right`，有配图时附加 `images` 数组，图片使用 `base64://` 内容。可见范围分别为所有人 `1`、好友 `4`、仅自己 `64`。发布成功后保存客户端、账号、时间和返回的 `tid`；发布中断或结果未能确认时，可在发布记录中核对结果。

连接检查读取客户端信息和登录账号。实际发布结果以发布接口的返回为准。NapCat 需要适配器提供空间 Cookie 获取接口。Cookie 仅在本次发布过程中使用。网页图片上传与发布各使用 60 秒请求超时；图片上传完成后才提交正文。上传失败保留草稿，提交后结果不明的记录显示「待核对」。

NapCat 网页发布使用 `https://up.qzone.qq.com/cgi-bin/upload/cgi_upload_image` 上传图片，使用 `https://user.qzone.qq.com/proxy/domain/taotao.qzone.qq.com/cgi-bin/emotion_cgi_publish_v6` 提交说说。正文为 `con`，权限仍为 `ugc_right`；图片上传后返回的信息组成 `pic_bo`、`richval`，成功响应中的 `tid` 保存为说说 ID。

### 图片角色设定

`diary.image_character_enabled` 开启共用角色卡，`image_character_appearance` 和 `image_character_clothing` 分别保存外貌与常用穿着，长度上限为 800、400 字符。构图结果 `character_visible` 表示麦麦是否入镜，记录中保存为 `image_character_visible`。人物画面在请求生图服务时加入角色卡；物件画面使用场景描述和画风。

聊天工具 `maiweave_show_life` 的可选参数 `framing` 传递本次展示要求，最多 300 字符，结合当前经历生成画面描述。角色卡原文只进入图片请求，沿用现有聊天上下文预算。配图模型使用最多 4000 字符正文、1200 字符已有画面描述和 300 字符展示要求；新画面描述最多 1200 字符。

空间自动配图复用空间文案模型的构图结果。手动空间配图与聊天配图使用图片生成提示词模型补充构图及入镜判断。已有生活图片按经历内容复用，修改角色卡用于新图，图片清理沿用现有保留设置。


角色参考图通过 `diary.image_character_reference_enabled` 开启，在「此刻生活 → 角色与图片」上传，也可以填写 `diary.image_character_reference_url`。人物画面读取参考图，与文字生图共用地址、密钥、模型和图片保存流程。人物外貌以参考图为准，文字角色卡补充其他细节。

角色与图片页面调用 `ui_generate_character`，使用公开的 `config.get("personality")` 读取人设、复用「配图提示词」模型与用量记录。生成结果直接填入外貌与穿着，用户修改后保存。


图片接口格式通过 `diary.image_reference_protocol` 选择。OpenAI Chat 使用 `/chat/completions`；Gemini 原生使用 `generateContent` 与 `inlineData`；DashScope 多模态使用同步多模态生成接口。「参考图随生成请求发送（豆包方舟、通义兼容）」对应配置值 `通义千问兼容接口`，在 `/images/generations` 的 JSON 中携带 `image` Data URL；OpenAI 图片编辑沿用 multipart `/images/edits`。`ui_character_image` 查询预览，`ui_character_image_action` 提供上传和移除操作。页面依次调用 begin、append、finish 上传，append 的 `content` 为 Base64 分块，每块最多 32768 字符，图片总量最多 512 KiB；abort 清除上传中的临时文件，remove 移除已上传图片。当前参考图保存在插件数据目录 `character_reference.jpg`，替换覆盖该文件，优先于配置直链。参考图单独保留，生活图片继续按原有规则清理。

角色与图片页面的 `ui_save_character(content)` 接收 JSON 字符串，保存角色外貌、穿着、参考图开关与直链、两类画风和负面提示词。字段沿用原有 `diary` 字段名，读取接口 `ui_character_image` 的 `settings` 返回当前值，`draft` 返回生成的外貌与穿着草稿。业务设置保存在现有生活记录的 `image_settings/character`，首次加载从旧配置迁入；模型连接仍由 MaiBot 配置管理。

图片描述的结构化结果包含 `selfie`，表示前置自拍，保存为 `image_selfie`。自拍同时视为人物入镜，按角色设置使用角色卡与参考图。聊天和空间沿用现有描述调用完成判断；前置自拍把持机手留在镜头外，对镜自拍把手机和倒影纳入画面，固定生图测试沿用物件场景。手动改写画面描述时清除上次的自拍标记，再按当前流程生成。

「角色与图片」中的试画复用 `ui_test_image(scene, prompt)`，场景支持自拍和物件近景，场景描述最多 1000 字符。试画使用聊天画风，自拍沿用角色卡和参考图设置；不传场景时使用配置测试的茶杯与绿植画面。`ui_character_trial` 返回最近一次结果、模型、日期、用时、请求超时、请求与返回尺寸及图片预览。两种测试共用 `image_test/latest`，按现有图片保留设置清理。
