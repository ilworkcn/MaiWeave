# 架构与接口

## 模块

| 文件 | 职责 |
| --- | --- |
| `plugin.py` | 生命周期、基础工具、3 个 Hook、状态指令与首页入口 |
| `config.py` | SDK 配置模型 |
| `anniversaries.py` | 个人资料、纪念日和公历／农历逐年换算 |
| `models.py` | 业务输入类型和日期转换 |
| `engine.py` | 计划、经历、目标、关系和生活推进 |
| `living.py` | 调用宿主模型选择活动，提交主动交流请求 |
| `store.py` | 插件专用 SQLite 记录存储 |
| `memory.py` | 原生记忆 HTTP 连接 |
| `world.py` | 真实天气、订阅与宿主联网资料 |
| `spatial.py` | 地点图、最短耗时路线与活动前出行 |
| `rhythm.py` | 重复规则展开与基于完成记录的习惯学习 |
| `dreams.py` | 独立梦境档案和醒后心情 |
| `continuity.py` | 具体模拟结果、语义归类、体验偏好、阶段目标和持续话题 |
| `feature_tools.py` | 六个扩展自然语言工具 |
| `webui.py` / `webui.json` | 只读页面查询、操作 API 和十页中文工作区 |

数据量面向单个角色，使用一张按类别和 ID 区分的 JSON 记录表，避免为尚未出现的查询场景构造仓储框架。写操作使用 SQLite 事务。未引入额外消息队列、向量检索、事件总线或通用迁移系统。

## 状态转换

```text
scheduled → active → completed（独自模拟）
                   → awaiting_confirmation（共同安排或非模拟）
active → paused → active
scheduled → blocked（后续固定安排无法按时到达）→ scheduled（调整后恢复）
scheduled / active / paused / awaiting_confirmation → cancelled
记录带 plan_id 的已发生经历 → completed
```

取消后仍可补录实际发生的经历，取消历史保留。一个计划只记录一次完成，后续补充修改原经历。计划 ID 不随标题和时间变化。

状态推进按现有计划的开始和结束边界分段，因此跨午夜和离线恢复不会重复结算完成事件。没有计划的时间只影响身体状态，不生成生活故事。

具体活动结果在完成记录之后生成，只补充独自模拟活动；用户已修订的内容保持不变。语义归类同时服务习惯学习与作品接续，偏好保留对应经历 ID。分阶段目标以结果中的有效进展推进，未分阶段的旧目标继续按完成次数累计。

空间重算沿当前地点、正在进行的活动、后续活动顺序计算。自动生成的出行是活动的派生安排；固定活动冲突进入 blocked，可变动活动让出固定时段并顺延。持续情绪采用按时间衰减的事件影响，跟进事项仅记录具体话题与请求状态，不建立通用记忆库。

## 宿主接口

- 使用 SDK 2.21 的插件工厂、配置模型、工具、首页卡片和命名 Hook。
- 接收 Hook 只消费完整的状态指令，在聊天存储和观察前结束处理。先通过 `chat.open_session` 打开原生会话，再发送不入库、不同步历史的状态回复。
- Planner Hook 注入 `SystemMessageItem`；Replyer Hook 追加 `extra_prompt`，自然语言操作仍经过原生对话流程。
- 会话与用户取自宿主提供的 `stream_id`、`user_id`。
- 主动交流使用 `ctx.maisaka.proactive.trigger()`。
- 原生记忆通过 WebUI 的 A_Memorix HTTP 接口查询、创建与更新，不直接访问宿主数据库。
