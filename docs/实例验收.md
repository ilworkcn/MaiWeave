# 实例验收

本项目尚未连接真实 MaiBot 实例。以下步骤用于在部署实例上确认模型、平台和记忆配置，不能用单元测试结果代替。

1. 加载插件，确认没有清单、配置或 Hook 注册错误；发送 `/maiweave` 能返回状态。
2. 暂时关闭自主生活，说“明天七点到八点一起看电影”，确认工具成功，并再次查询。
3. 改到八点到九点，确认事件 ID 不变；取消后确认不再列为待办。
4. 创建一个很快结束的共同安排，过时后应显示待确认，不应自动声称用户已经参加。
5. 明确说明活动已经完成，检查经历与计划关联；补充地点，检查修订历史。
6. 重载插件，确认计划、经历和状态仍然存在。
7. 开启自主生活，检查在空闲时调用已配置的宿主模型；已有计划不能被覆盖。
8. 睡眠时段检查角色活动和精力推进。正常聊天不被插件强制阻断，可以明确暂停睡眠活动后再恢复。
9. 填写原生记忆连接，记录用户陈述的经历；在 WebUI 原生事实记录中核对来源、聊天流和文本。
10. 更正同一经历，确认返回的原生记忆 ID 已保存，旧内容按宿主规则修订。模拟经历不应出现于原生事实账本。
11. 配置允许主动交流的聊天流，记录一条重要经历；核对宿主是否接受请求。宿主沉默不代表发送失败，插件不伪造送达。
12. 使用另一聊天流查询，确认只显示公共自主活动和当前流记录。
13. 重载插件并刷新浏览器，在插件配置页检查中文字段名称、开关、数字和列表控件；进入「MaiWeave · 生活」，检查八个页面与状态趋势。
14. 填写天气城市，点击更新天气，检查地点、观测时间和三日预报；填写一个有效 RSS/Atom 订阅，确认资讯有原始来源。
15. 开启宿主联网搜索，检索一个主题并阅读结果网页，检查后台任务和资料记录。
16. 安排一小时后在图书馆阅读，确认自动生成提前21分钟出发的路线；取消阅读应同时取消未完成的出行。
17. 从住处前往图书馆，检查途中先到街道，尚未到达时不能直接显示在图书馆；暂停再恢复，路段进度继续累计。
18. 新建每天晚间阅读的重复规则，确认只生成预排窗口内安排；跳过一天、修改时间、停止规则，检查未来安排同步更新。
19. 完成足够长的睡眠，检查独立梦境档案和醒后心情；原生事实账本不应出现梦境。生成失败时页面明确显示原因。
20. 连续三个不同日期完成同名活动，检查习惯时间、观察天数和依据；忽略后该习惯不再优先参与自主活动。

出现问题时记录 MaiBot 版本、SDK 版本、`/maiweave` 输出和对应异常日志。无需先增加兼容代码或多层兜底。
